# 审查报告规范

## 1 目录结构

```
docs/reports/
├── README.md                              # 本文件，规范说明
├── INDEX.md                               # 文档索引
└── YYYY-MM-DD-${subject}-${type}.md       # 报告文档
```

## 2 文档元信息

报告文档使用简化的元信息：

```markdown
> **日期**: 2025-12-27
> **审查人**: Claude / 用户名
```

## 3 命名规范

报告文档使用日期前缀，便于按时间排序：

| 类型 | 命名模式 | 示例 |
|------|----------|------|
| 代码审查 | `YYYY-MM-DD-${subject}-review.md` | `2025-12-27-auth-review.md` |
| 实施评估 | `YYYY-MM-DD-${subject}-assessment.md` | `2025-12-27-cache-assessment.md` |
| 完成验证 | `YYYY-MM-DD-${subject}-verification.md` | `2025-12-27-init-verification.md` |
| 方案评价 | `YYYY-MM-DD-${subject}-evaluation.md` | `2025-12-27-auth-evaluation.md` |

## 4 文档模板

### 4.1 代码审查模板

```markdown
# ${Subject} 代码审查

> **日期**: YYYY-MM-DD
> **审查人**: xxx

## 1 审查范围

描述本次审查覆盖的代码范围。

## 2 发现的问题

### 2.1 严重问题

- 问题描述
  - **位置**：文件路径:行号
  - **建议**：修复建议

### 2.2 一般问题

- 问题描述

### 2.3 建议改进

- 改进建议

## 3 总结

总体评价和结论。
```

### 4.2 完成验证模板

```markdown
# ${Subject} 完成验证

> **日期**: YYYY-MM-DD
> **验证人**: xxx

**关联计划**: [计划文档](../plan/xxx/implementation.md)

## 1 验证范围

描述本次验证覆盖的功能范围。

## 2 验证结果

### 2.1 功能验证

| 功能点 | 结果 | 备注 |
|--------|------|------|
| 功能 1 | PASS/FAIL | 备注 |

### 2.2 测试覆盖

| 模块 | 覆盖率 | 要求 |
|------|--------|------|
| 模块 1 | 85% | 80% |

## 3 遗留问题

- 问题描述

## 4 结论

验证通过/不通过，说明原因。
```

## 5 检查清单

完成报告文档前，确认以下事项：

- [ ] 文件命名包含日期前缀
- [ ] 包含元信息（日期、审查人）
- [ ] 已更新 `INDEX.md` 索引
- [ ] 如有关联计划，已添加链接
